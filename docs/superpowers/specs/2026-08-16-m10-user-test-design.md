# M10 사용자 테스트 — 설계

작성일 2026-08-16. 근거: `docs/기획안.md` §12.2-B · §12.9 · §12.10 · §13.

## 무엇을 만드는가

M10의 완료 기준은 **완료 시간·완료율·오탐색률 실측**이고, 그것은 참가자 8명(60대 이상 5,
40~50대 3)을 앉혀야 나온다. 이 스펙이 다루는 것은 **사람을 앉히는 날까지 준비되어 있어야
하는 것**이다. 세션 운영 자체는 이 스펙 밖이다.

산출물 넷:

| 산출물 | 성격 |
|---|---|
| `docs/사용자테스트-키트.md` | 진행자가 인쇄해 들고 가는 물건 — 지시문·대본·동의서·기록 양식 |
| `frontend/src/instrumentation/SttBridge.tsx` | F9 프로토콜용 음성 주입 손잡이 (새 코드) |
| `tools/src/report-usertest.ts` + 테스트 | 회수한 세션 JSON → 1차 지표 표 |
| `docs/기획안.md` §12.10·§13 갱신 | 준비 완료를 기록하고, 아래의 발견을 반영 |

## 먼저 고칠 것 — §12.10의 사실 오류

§12.10 "이미 되어 있는 것"에 **음성 주입**이 올라 있다. 실제로는 없다.
`MockSttProvider`는 `frontend/test/prefill.test.tsx`·`scenarios.test.tsx`에서만 쓰이고,
실행 중인 앱(`frontend/src/stt.ts`)은 `FallbackSttProvider`로 진짜 마이크만 쓴다.

F9의 "일부러 틀린 금액을 띄운다"가 이것 없이는 성립하지 않으므로, 손잡이를 만들고
§12.10의 그 줄을 "준비해야 할 것"으로 옮긴다.

## 1. 과제 세트

과제 3개를 두 모드로 각각(실질 6회), 그 뒤에 F9 프로토콜 1회와 M7 반복 1회.
**지시문에 메뉴 이름을 넣지 않는다** — 넣으면 그 말을 그대로 검색창에 치므로,
재려던 것(사용자가 그 기능을 뭐라고 부르는가)이 사라진다(§12.10).

### T1 자주 쓰는 것 → `inquiry.balance`

> "이번 달 관리비가 빠져나갔는지 궁금하세요. 통장에 얼마 남았는지 보세요."

§12.4에서 탭 차이가 **0%**였던 자리다. 볼 것은 **탭이 0:0인데 완료 시간이 갈리는가**.
갈리면 §12.4가 말만 하고 수치를 못 댄 주장 — "탭 횟수는 난이도의 하한이고 조밀한 UI에
유리하게 편향된다" — 이 처음으로 근거를 얻는다. 안 갈리면 그 주장도 그대로 접는다.

### T2 찾아야 하는 것 → `transfer.auto`

> "매달 자동으로 나가는 전기요금이 있는데, 이제 그만 나가게 하고 싶으세요."

§2.2의 주장("실패는 자주 쓰는 기능이 아니라 찾아야 하는 기능에서 일어난다")이 걸린 자리.
볼 것: 오탐색률 · **어떤 낱말로 부르는가**(M7의 근거) · 되묻기 선택지 3개가 적당한가(§9.2).

### T3 이름을 모르는 것 → `settings.limit`

> "은행에서 '한 번에 보낼 수 있는 돈이 막혀 있으니 앱에서 푸세요'라고 했습니다."

볼 것: 완료율 · 뜻풀이(F7)를 읽는가.
`auth.certificate`를 대안으로 두되 기본은 `settings.limit`이다 — 공동인증서는 이름은
알고 자리를 모르는 쪽이고, 이체 한도는 이름 자체를 모르는 쪽이라 F7에 더 가깝다.

### F9 프로토콜 (두 모드가 끝난 뒤, 쉬운 모드에서 1회)

참가자가 "삼십만원"이라 말하면 진행자가 **십삼만원** 전사를 미리 넣어 둔다.
세 갈래로 갈리고 셋의 뜻이 전부 다르다(§12.10의 표를 그대로 쓴다).

| 관찰 | 뜻 | 기록 값 |
|---|---|---|
| 읽고, 틀렸으니 안 누른다 | 제안이 안전 장치로 작동한다 | `read-not-tapped` |
| 안 읽고 누른다 | 탭 한 번을 더 요구했을 뿐, 안전은 늘지 않았다 | `tapped-unread` |
| 아예 안 누르고 직접 친다 | 금액을 아예 읽지 않는 편이 정직하다 | `typed-instead` |

### M7 반복 (F9 뒤)

T2를 한 번 더 시킨다. 처음과 **같은 낱말**을 쓰는지만 본다.
다르면 개인 동의어 학습("정확히 같은 말일 때만 걸린다")의 값이 사라진다.

### 세션 중 상시 관찰 (과제에 묶지 않음)

- 카드가 바뀐 것을 알아채는가 · 바뀐 이유를 궁금해하는가 (F3)
- "왜 이렇게 보이나요?"를 찾아 들어가는가 · 읽고 납득하는가 (F8)
- 사후 인터뷰: 온보딩 두 문항이 값을 하는가(F5) · 카드가 하루 두 장 바뀌면 혼란스러운가(§8.2)

### 순서

참가자 홀수 번호는 쉬운 모드 먼저, 짝수는 기본 UI 먼저 (counterbalancing).

## 2. 진행 대본

### 개입 기준 — 숫자로 못 박는다

§12.10이 "개입 시점이 사람마다 다르면 완료율이 진행자의 인내심을 재게 된다"고 적었다.

| 조건 | 진행자가 하는 말 | 기록 |
|---|---|---|
| 60초 무진전 (새 화면 진입 없음) | "지금 무엇을 찾고 계신지 말씀해 주시겠어요?" | 개입 1 |
| 추가 60초 무진전 | "화면에서 눈에 들어오는 걸 소리 내어 읽어 주세요." | 개입 2 |
| 추가 60초, 또는 참가자가 포기 의사 | "여기까지 하겠습니다." | 중단 (미완료) |

진행자 금칙: 메뉴 이름 말하기 · "거기 아니에요" · 화면 가리키기 ·
참가자가 옳은 방향일 때 고개 끄덕이기. 넷 다 완료율을 진행자가 만들어 낸다.

think-aloud 유도는 **침묵 15초에 한 번만**. 계속 재촉하면 말하느라 완료 시간이 늘어난다 —
재려는 것을 재는 행위가 바꾼다.

## 3. 동의서

화면 녹화와 발화 기록에 대한 것. §11.2에 맞춘다.

- 음성 원본은 **분석 후 폐기**
- 이름·계좌번호·금액은 데모 계정계의 가짜 값이므로 수집 대상이 아니다
- 기록은 P01~P08 번호로만 남는다
- 언제든 중단할 수 있고, 중단해도 불이익이 없다

## 4. 기록 양식

A4 한 장, 과제당 한 줄. **자동 계측이 못 잡는 것만** 적는다.

멈춘 지점(화면 이름) · **쓴 낱말을 원문 그대로**(M7의 근거이므로 요약하지 않는다) ·
개입 횟수와 단계 · 신호(한숨·"이게 뭐야"·되돌아가기) · F9 세 갈래 중 어디.

## 5. 음성 주입 손잡이 — `SttBridge.tsx`

`MetricsBridge`와 같은 패턴. 화면에 아무것도 띄우지 않고 진행자만 콘솔에서 잡는다.

- `?stt=script`로 열었을 때만 실제 STT를 `MockSttProvider`로 바꾼다.
  **플래그가 없으면 지금과 완전히 동일** — 기본 경로에 손대지 않는다
- 진행자가 `minuiStt.next("우리 딸한테 십삼만원 보내줘")`로 다음 전사를 정해 둔다
- 참가자는 평소처럼 마이크 버튼을 누르고 말한다. 앱은 넣어 둔 전사를 받는다
- `next()`를 안 부르면 마이크가 정상 동작한다 — F9 과제 외에는 진짜 음성으로 잰다

`frontend`는 배포물이 아니다(AGENTS.md 폴더 경계). `packages/*`는 건드리지 않는다.

## 6. 집계 도구 — `tools/src/report-usertest.ts`

`pnpm --filter tools report:usertest`.
`report-metrics.ts`가 "측정 안 함"으로 비워 둔 세 칸을 채우는 짝이다.

### 입력 — 세션 봉투

`TaskRun[]`에는 참가자도 순서도 없으니 봉투를 씌운다. 참가자당 파일 하나를
`tools/sessions/P01.json`에 둔다.

```json
{
  "participant": "P01",
  "ageBand": "60+",
  "firstMode": "minui",
  "runs": [ /* copy(minuiMetrics.toJSON()) 그대로 붙여넣기 */ ],
  "interventions": { "T2:classic": 2 },
  "words": { "T2": ["자동으로 나가는 거", "그 매달 빠지는 거"] },
  "f9": "read-not-tapped",
  "m7Repeat": "same"
}
```

- `ageBand`: `"60+"` | `"40-50"`
- `firstMode`: `"minui"` | `"classic"`
- `runs`: `TaskRun[]` (`frontend/src/instrumentation/TaskRecorder.tsx`의 형).
  `taskId`는 `"T1"`·`"T2"`·`"T3"`, F9는 `"F9"`, M7 반복은 `"T2-repeat"`로 연다.
  T2가 세 번(두 모드 + 반복) 돌기 때문에 반복분을 같은 id로 열면 지표에 섞인다.
  **`T2-repeat`와 `F9`는 1차 지표 집계에서 뺀다** — 학습 효과가 실린 수행이고,
  F9는 시간이 아니라 세 갈래를 보는 과제다
- `interventions`: `"<taskId>:<mode>"` → 개입 단계 (3이면 중단)
- `words`: 과제별로 참가자가 쓴 낱말, **발화 순서대로, 원문 그대로**.
  `words.T2`의 첫 원소가 T2 첫 수행, 마지막 원소가 `T2-repeat`의 발화다
- `f9`: 세 갈래 중 하나. 미수행이면 필드를 뺀다
- `m7Repeat`: `"same"` | `"different"`. 미수행이면 필드를 뺀다

`tools/sessions/`는 `.gitignore`에 넣고 `EXAMPLE.json`만 저장소에 남긴다 —
실제 참가자 기록이다.

### 판단 셋

1. **평균이 아니라 중앙값 + 개별 값 전부를 찍는다.** 8명에서 평균은 한 명이 흔든다.
   `72s [41,55,68,76,89,94,120,203]`처럼 원자료를 옆에 남겨 독자가 직접 본다.
2. **진행자가 중단한 과제(개입 3)는 완료 시간 계산에서 뺀다.** 미완료로는 세지만,
   그 시각은 참가자의 수행 시간이 아니라 진행자가 60초를 셋 셌다는 사실이다.
   넣으면 완료 시간이 진행자의 인내심을 잰다.
3. **순서 효과를 따로 찍는다.** counterbalancing이 8명에서 상쇄된다는 보장이 없다.
   "먼저 한 모드 / 나중 한 모드"를 별도 줄로 내서 상쇄 여부를 눈으로 본다.
   상쇄가 안 됐으면 그것도 그대로 보고한다.

### 출력

```
═══ M10 1차 지표 — 참가자 8명 (60+ 5, 40-50 3) ═══

완료 시간 (중앙값)      쉬운 모드    기본 UI      차이
  T1 잔액                    12s        18s      -33%
     [8,11,12,13,...]   [9,15,18,22,...]
  ...
완료율                  7/8 (88%)   6/8 (75%)
오탐색률 (과제당)            0.4        1.1

순서 효과 — 먼저 한 모드 45s / 나중 한 모드 31s  ⚠ 상쇄 안 됨

F9  읽고 안 누름 5 · 안 읽고 누름 2 · 직접 침 1
M7  같은 말 6/8

표본 8명 — 유의성 주장 없음. 관찰된 패턴과 개별 사례로 읽을 것.
```

세션 파일이 하나도 없으면 `report-metrics.ts`와 같은 원칙으로 **"미측정"을 그대로 찍고
끝낸다.** 있는 것만 채운다. 목표를 맞추려고 기준을 옮기지 않는다.

### 테스트 (TDD)

`tools/test/report-usertest.test.ts`:

- 중단한 과제가 완료 시간에서 빠지는가 (미완료로는 세는가)
- 중앙값이 짝수 개 표본에서 맞는가
- 세션 0개면 "미측정"을 찍는가
- 봉투가 깨졌으면(필드 누락·모드 오타) 조용히 넘기지 않고 실패하는가
- 순서 효과가 `firstMode`대로 갈라지는가

## 하지 않는 것

- **참가자 모집·세션 운영·결과 해석.** 사람이 있어야 한다
- **§12.1 표의 세 칸을 지금 채우는 것.** 세션 전에 채우면 그 표가 거짓이 된다
- **통계 검정.** 표본 8명에 검정력이 없다. 도구가 p값을 계산하면 안 된다
- `packages/*` 변경. 이식 계약을 넓히지 않는다
