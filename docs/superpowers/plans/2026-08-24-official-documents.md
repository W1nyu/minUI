# 공식 문서로 검색의 벽을 넘는다

> **다음 세션은 이 문서부터 읽는다.** "작업 진행"이라고 하면 아래 Task 1부터 시작한다.
> 작성 2026-08-24. 앞선 세션에서 M11의 검색 개선을 세 번 시도해 세 번 다 실패했고,
> **그 실패들이 같은 원인을 가리켜서** 이 계획이 나왔다.

## 왜 이걸 하는가 — 측정이 여기로 몰았다

M11에서 원격 신경망 검색을 붙이고 `semantic-focus` 558건에서 **12.4%**를 얻었다.
그 값을 올리려고 세 지렛대를 당겼고 **셋 다 실패했다.**

| 시도 | 결과 |
|---|---|
| 하이브리드 (dense+sparse) | **진단이 틀렸다.** `recall@20`이 50.9% — 회수기가 문제가 아니었다 |
| 교차 인코더 재순위 | **12.4% → 5.7%** (더 나쁨). 지연 p50 3,586ms / p95 5,915ms (게이트 1,200ms의 5배) |
| 문서에 뜻풀이(`hint`) 넣기 | **순환.** blind +31.7%p인데 **사람이 쓴 질의 −6.7%p** |

### 회수 곡선 (bge-m3, 재순위 없음)

```
recall@1    12.4%
recall@3    21.9%
recall@5    28.7%
recall@10   38.5%
recall@20   50.9%
recall@50   67.6%
```

### 뜻풀이 A/B (2026-08-24)

```
                    뜻풀이 뺌    뜻풀이 넣음
blind-paraphrase      12.4%   →   44.1%    (+31.7%p)
legacy-regression     62.7%   →   56.0%    (−6.7%p)   ← 사람이 쓴 질의
```

blind 질의는 그 뜻풀이를 보고 쓴 것이라 오르는 게 당연하고, 사람 질의에서는 떨어진다.
§16의 85%→67%와 같은 모양이다. **모델이 쓴 글을 색인에 넣으면 그것에서 파생된 지표만
오르고 실제 사용자는 손해를 본다.** `menuDocument`의 `includeHint`는 기본 false로 두고
이 수치를 doc 주석에 박아 뒀다.

### 진짜 원인 — 삼중 확인됨

```
문서에 사용자 언어가 있을 때 (legacy, 사람 동의어 121개 포함)   62.7%
없을 때 (semantic-focus)                                        12.4%
```

**모델이 나쁜 게 아니다. 2,948개 메뉴 중 121개(4%)에만 사용자 언어가 있는 것이 문제다.**
이건 이 프로젝트가 커밋 `6ca4f66`에 이미 적어 둔 것이다:

> 필요한 건 용어 대응이 아니라 **사람이 그것을 뭐라 부르는가**이고, 그 정보는 라벨 안에 없다.

**없는 정보는 어떤 검색기도 재순위도 만들어 내지 못한다.**

### 사용자 언어를 넣는 길 넷 — 셋이 막혔다

| 출처 | 상태 |
|---|---|
| 사람이 손으로 (121개) | 비싸다. 2,948개는 불가능 |
| M7 학습 (기기별) | 이미 있다. 다만 **실사용자가 있어야** 쌓인다 (M10 대기 중) |
| 모델이 쓴 뜻풀이 | **막혔다** — 순환이고 사람 질의를 해친다 |
| **공식 문서** | 금융사 사이트에 이미 있고 **수집기가 이미 긁을 수 있다** ← 이 계획 |

공식 문서는 **은행이 쓴 글**이라 순환이 없고, 상품설명서·약관·안내 페이지에는 사용자가
쓸 법한 말이 실제로 들어 있다. 그리고 같은 문서가 **「이해 지원」 기둥**도 채운다 —
검색과 설명이 하나로 풀린다.

## 무엇을 만드는가

### 두 가지를 동시에 얻는다

1. **검색 개선** — 메뉴 벡터의 문서에 공식 설명을 넣어 사용자 언어 커버리지를 올린다
2. **이해 지원** — "이 상품 뭐가 안 좋아요?"에 **출처 문장과 함께** 답한다 (불완전판매 대응)

README의 「공모전 핵심」 네 기둥 중 **의미 탐색**과 **이해 지원**을 같은 재료로 채운다.

### 안전 경계는 그대로

- 읽기 전용. 거래 없음
- **출처 필수** — 근거 문장을 못 대면 답하지 않는다. "모른다"가 틀린 답보다 낫다
- `riskLevel` 규칙과 §9.3 경계는 손대지 않는다 (절대 보호선 4·8)
- AI가 없거나 실패하면 기존 검색·전체 메뉴로 돌아간다

### 안전장치를 테스트가 아니라 **런타임 코드**로 뒀다

모델이 낸 인용을 문서 본문에서 실제로 찾고, 못 찾으면 그 답은 나가지 못한다. 그리고
화면에 나가는 문장은 **모델이 쓴 것이 아니라 문서에서 잘라 온 원문**이다 — 찾았다는
것과 옮겨 적은 것이 같다는 것은 다르고, 한 글자라도 다르면 그것은 이미 인용이 아니다.

공백 차이만 무시한다. 구두점이나 조사까지 봐주면 "비슷한 문장"이 통과하고, 그러면
대조는 통과 도장으로만 남는다.

```
버린 것              2개  — 근거를 못 댔다
```

버린 둘은 옳게 버렸다. `소비자보호우수사례`의 근거로 온 것은 지역 업무협약 보도자료
문장이었고, `자주하는 질문`의 근거로 온 것은 **그 쪽의 제목 한 줄**(`자주하는 질문(FAQ)`)이었다.
제목이 근거가 되면 모든 문서가 자기 제목으로 자기를 증명하게 되므로, 인용 하한을
12자에서 **20자**로 올려 막았다.

### 재면서 고친 것 하나 — 상한이 멀쩡한 답을 죽이고 있었다

처음 돌렸을 때 9개 중 6개가 버려졌다. 인용이 틀려서인 줄 알고 원인을 찍어 보니
**여섯 중 다섯은 설명이 45자를 넘겨서** 죽은 것이었고, 그 다섯은 인용까지 통과한
멀쩡한 답이었다. `hint.ts`가 이미 적어 둔 함정과 같은 모양이다 — 상한이 하필
필요한 것만 걸러 낸다.

상한을 늘리지 않았다. 이 답은 전체 메뉴 목록 안에 인용 한 줄과 함께 놓이므로 길어지면
읽을 것을 줄이려던 기능이 읽을 것을 늘린다. 대신 **길이로 걸린 경우에만 한 번 다시
묻는다**(`explainWithSource`). 인용을 못 댄 답은 다시 묻지 않는다 — 다시 물어도 문서에
근거가 없다.

### 남은 한계 — 이것은 아직 못 잰다

대조가 보증하는 것은 **그 문장이 문서에 있다**는 것이지, **그 문장이 그 설명을
뒷받침한다**는 것이 아니다. 실제로 `외화예금`의 근거로 예금자보호법 문장이,
`인터넷 뱅킹`의 근거로 해외 IP 차단 서비스 문장이 붙었다. 둘 다 그 문서에 실재하는
문장이고 주제도 멀지 않지만, 설명을 직접 떠받치지는 않는다. 관련성은 문자열로 잴 수
없으므로 지금 구조로는 못 막는다 — **모르는 것을 아는 척하지 않기 위해 여기 적어 둔다.**

### 함정 (겪은 것들)

- **배치를 안 자르면 조용히 나빠진다.** 인코더에 930개를 통째로 넣어 700MB 할당 실패.
  터지지 않을 때가 더 나쁘다 — 패딩으로 벡터가 망가진다. `BATCH = 32` / 재순위 16
- **`text-classification` 파이프라인은 시그모이드로 포화한다.** 재순위는
  `AutoModelForSequenceClassification`으로 **원시 로짓**을 읽어야 한다
- **vite 플러그인은 `apply: "serve"`** — 안 그러면 프로덕션 빌드가 모델 600MB를 불러온다
- **데모 slug ≠ 카탈로그 파일명** (`hana`↔`kebhana`, `kb`↔`kbstar`). `sites.ts`의
  `catalogId`가 유일한 대응표다
- **core는 시간을 못 잰다** (`portability.test.ts`가 `setTimeout`을 잡는다).
  원격 타임아웃은 `MinUIProvider`가 씌운다
- **화면 테스트는 다이얼로그 안으로 범위를 좁혀라** — `screen`으로 찾으면 뒤의 홈 카드를
  잡아 테스트가 잘못된 이유로 통과한다
