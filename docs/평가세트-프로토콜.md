# 평가 세트 프로토콜

> 2026-08-24 개정 — 문자열 겹침을 데이터 무효 판정으로 쓰던 방식을 폐기했다.

평가의 목표는 좋은 수치를 지키는 것이 아니라, **다음 제품 결정을 더 잘하게 하는 것**이다.
데이터에 한계가 있으면 그 수치가 답할 수 있는 질문을 좁힌다. 기존 회귀·사용성 데이터를
"오염"이라고 버려 프로젝트를 멈추게 하지 않는다.

## 1. 두 층위, 두 질문

질의와 정답 표현의 문자열 겹침은 `tools/src/eval-contamination.ts`가 같은 정규화 규칙으로
계산한다. 이 값은 데이터의 품질 등급이 아니라 검색 경로에 대한 정보다.

| 층위 | 정의 | 답하는 질문 | 쓰지 않는 주장 |
|---|---|---|---|
| `lexical-support` | 라벨·동의어와 포함, 2-gram, 공통 문자열 신호가 있음 | 실제 표현, 정확 매칭, 동의어, n-gram 경로가 퇴행하지 않았는가 | 이 세트만으로 신경망의 **추가** 이득을 증명 |
| `semantic-focus` | 위 문자열 신호가 없음 | n-gram을 넘어 의미 매칭이 추가로 회수하는가 | 실제 고령 사용자 전체의 성능 |

정답 표현을 그대로 말한 사용자가 잘못된 데이터를 만든 것은 아니다. 그 발화는 사용자가
바로 찾을 수 있어야 하는 기능의 회귀 테스트다. 반대로 신경망을 붙였을 때의 이득을 알고
싶다면, 그 경로가 못 푸는 `semantic-focus`를 별도 비교한다.

`isClean()`은 이전 코드와의 호환을 위해 남아 있지만 보고서에서는 `semantic-focus`라는
이름을 쓴다. "깨끗하지 않다"는 표현은 데이터 폐기나 서비스 품질의 부정을 뜻하지 않는다.

## 2. 출처는 숨기지 않고 기록한다

각 질의에는 `source`를 넣는다. 추천 값은 아래 네 가지다.

| `source` | 강점 | 한계 |
|---|---|---|
| `legacy-regression` | 알려진 기능과 기존 표현의 퇴행을 빠르게 잡음 | 저자 노출과 문자열 신호가 많을 수 있음 |
| `blind-paraphrase` | 라벨·id·동의어를 보지 않은 바꿔말하기로 의미 회수를 넓게 탐색 | 실제 사람의 말투를 대표하지 않음 |
| `thirdparty` | 정답을 보지 않은 제3자 발화 | 표본이 작거나 과제 선택 편향이 있을 수 있음 |
| `usertest` | 실제 수행 중 나온 발화와 성공·실패를 연결 | 표본·기기·진행 방식에 의존 |

서로 다른 출처의 결과를 운영 현황으로 합산할 수는 있다. 다만 합산 수치에는 반드시 출처별
표본 수와 층위를 붙이며, 이를 "의미 검색 정확도"처럼 한 가지 원인의 효과로 해석하지 않는다.

## 3. 실제 누출과 문자열 겹침을 구분한다

문자열 겹침은 정상적인 사용자 언어의 일부다. 막아야 할 것은 아래처럼 **평가 결과를 보고
답안이나 설정을 맞추는 누출**이다.

- 검증 세트의 실패를 보고 동의어·가중치·임계값을 고쳤다면, 그 세트는 이후 **회귀 세트**로
  남긴다. 같은 개선의 효과를 주장하는 검증 세트로 재사용하지 않는다.
- 블라인드 바꿔말하기와 제3자 문항지에는 라벨·메뉴 id·동의어를 넣지 않는다. 뜻풀이와
  갈래도 누출 위험을 기록하고, 필요한 경우 `semantic-focus`와 `lexical-support`로 다시
  층화한다.
- 새 개선의 효과를 검증해야 하면 새 버전의 홀드아웃 또는 새 사용자 세션을 추가한다.
  이전 세트를 영구 봉인해 개발을 막지 않는다. 세트 버전, 작성일, 수정 이유를 기록한다.

## 4. 보고 형식

정확도 보고는 최소한 다음 네 항목을 함께 낸다.

1. 비교한 구성과 변경한 설정
2. `source`와 층위별 표본 수
3. 1순위·후보 포함·되묻기·잘못된 확신처럼 제품 위험과 연결된 결과
4. 이 결과로 할 수 있는 주장과 할 수 없는 주장

호환을 위해 `report:contamination`은 유지하지만, 새 문서와 자동화에는
`report:evaluation`을 쓴다. 두 명령은 같은 용도별 보고를 출력한다.
기본 세트가 75건 중 1건만 `semantic-focus`여도 "수치 전부 무효"가 아니라 다음처럼 읽는다.

- 75건은 정상 표현과 현 검색 경로의 **회귀 지표**로 계속 쓴다.
- 1건은 신경망의 추가 이득을 말하기에는 너무 작으므로, 해당 주장에는
  `neural-queries`, 제3자 발화, 사용자 테스트를 추가한다.

## 5. 실행

```bash
# 기존 75건: 회귀·문자 경로의 비중과 현재 카탈로그 연결 확인
pnpm --filter tools report:evaluation

# 블라인드 바꿔말하기 세트: 신경망 의미 회수 후보의 층위 확인
pnpm --filter tools report:evaluation -- --set neural-queries

# 새 세트 생성과 신경망 비교
pnpm --filter tools build:eval-prompts
pnpm --filter tools build:eval-queries
pnpm --filter tools bench:neural
```

`bench:neural`은 `semantic-focus` 결과를 우선해 원격 검색의 추가 이득을 판정하고,
부정 질의의 잘못된 확신과 지연은 모든 관련 구성에서 계속 게이트로 둔다. `lexical-support`
결과도 함께 보고해 기존 사용자 표현을 희생하지 않았는지 확인한다.
