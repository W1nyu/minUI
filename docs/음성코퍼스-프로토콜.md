# 음성 코퍼스 프로토콜 (M21)

`docs/평가세트-프로토콜.md`의 자매 문서다. 저쪽이 **문자 질의**의 층위를 정했다면
이 문서는 **음성 발화**의 층위를 정한다. 규칙은 하나다 — 층위를 섞어 평균내지 않는다.

## 왜 이 코퍼스가 필요한가

이 프로젝트의 검색 수치는 전부 **손으로 친 텍스트**로 잰 것이다.

| 벤치 | 입력 |
|---|---|
| `bench:search` (미니은행 50) | 손으로 쓴 문장 |
| `bench:sites` (5곳 75) | 손으로 쓴 문장 |
| `bench:neural` | 손으로 쓴 문장 + 모델이 쓴 문장 |

간판 입력 경로인 **음성은 한 번도 실제 인식기를 지난 적이 없다.** "말로 찾기"가
얼마나 맞는지 이 프로젝트는 아직 모른다. 이 코퍼스가 그 공백을 메운다.

## 무엇을 남기고 무엇을 남기지 않는가

**오디오를 저장하지 않는다.** 남는 것은 문자열 쌍뿐이다.

| 남는다 | 남지 않는다 |
|---|---|
| 읽으라고 한 문장 (`intended`) | 음성 원본 — 화면이 애초에 손대지 않는다 |
| 인식기가 적은 말 (`heard`)과 대안 | 이름·나이·성별·연락처 |
| 익명 화자 id (`speaker`) | 어느 기기에서 모았는지 |
| 출처·TTS 속도·신뢰도 | 실제 계좌·금액·수취인 (프롬프트에 없다) |

기획안 §11.1의 수집 금지 목록(계좌번호·금액·수취인·음성 원본)과 충돌하지 않는다.
프롬프트는 이미 있는 평가 세트에서 오므로 숫자가 든 문장이 들어가지 않는다.

**다른 사람의 발화를 모을 때는 동의를 받는다.** 무엇을 왜 모으는지, 오디오가 남지 않는다는
것, 언제든 그만둘 수 있다는 것을 말로 알리고 시작한다. 기록에는 별칭만 남는다.

## 출처 세 층위 — 절대 평균내지 않는다

| 출처 | 무엇인가 | 무엇을 답할 수 있나 | 쓰임 |
|---|---|---|---|
| `tts-synthetic` | TTS를 스피커로 내보내고 마이크로 받은 것 | **STT가 금융 용어를 어떻게 틀리는가** (어휘적 오류) | 학습 |
| `self-recorded` | 본인이 직접 읽은 것 | 실제 발화 조건 — 속도·말끝·배경 소음 | 학습 |
| `thirdparty-recorded` | 다른 사람이 읽은 것 | **화자가 바뀌어도 되는가** | 홀드아웃 |

### TTS로 답할 수 없는 것을 미리 적어 둔다

**TTS는 젊고 명료하다. 고령자 발음 특성을 재현하지 못한다.** 발음이 뭉개지는 것,
말끝을 흐리는 것, 숨이 중간에 끊기는 것 — 이 프로젝트의 주 사용자가 실제로 겪는
그 조건들이 TTS에는 없다.

그러므로 **TTS 수치로 고령 사용자의 개선을 주장하지 않는다.** 리포트는 출처별 표본 수를
나란히 찍고, `bench:voice`가 두 층위를 각각 보고한다.

## 학습과 판정을 화자로 가른다

- **학습** — `tts-synthetic` + `self-recorded`. `fit:confusion`이 여기서만 비용을 배운다.
- **홀드아웃** — `thirdparty-recorded`. **고른 뒤 한 번만 본다.**

같은 사람의 발화가 양쪽에 있으면 그 사람의 버릇을 외운 것이 일반화로 보인다.
`bench:neural`이 사이트로 튜닝·검증을 가른 것과 같은 이유이고, 음성에서는 그 축이 화자다.

홀드아웃이 없으면 `bench:voice`가 학습 층위로 판정하되 **"잠정"이라고 찍는다.**

## 모으는 절차

```powershell
pnpm --filter tools build:stt-prompts          # 145건 (정답 있는 것 125 · 답 없어야 할 것 20)

$env:MINUI_STT_LAB=1; $env:VITE_MINUI_STT_LAB=1
pnpm --filter demos dev                        # → /stt-lab (포트는 vite가 정한다)
```

화면에서 출처와 화자 id를 고르고 「여기서부터 끝까지」를 누른다. 끝나면
`stt-corpus.json`을 내려받아 `tools/fixtures/stt-corpus.json`에 둔다.

### TTS 모드가 안 될 때

브라우저는 스피커로 나간 소리를 마이크로 되받아야 한다. Chrome의 에코 제거가 그 소리를
지우면 인식이 통째로 빈다. 그때는 시스템 루프백을 기본 입력 장치로 잡는다.

- Windows: 사운드 설정의 `Stereo Mix`(스테레오 믹스)를 켜서 기본 녹음 장치로
- 없으면 VB-Audio Virtual Cable 같은 가상 케이블
- 둘 다 안 되면 다른 기기에서 재생하고 이 기기의 마이크로 받는다

화면은 실패를 숨기지 않는다 — 실패도 한 줄로 남아 몇 건이 비었는지 바로 보인다.

### 얼마나 모으면 되는가

정해진 수는 없지만 기준은 있다. `fit:confusion`은 **두 번 이상 본 혼동만** 표에 넣는다.
자모 종류가 60개 남짓이므로, 흔한 혼동이 두 번씩 나오려면 **수백 줄** 단위가 필요하다.
프롬프트 145건을 TTS 목소리·속도를 바꿔 여러 번 돌리면 그 규모가 나온다.

## 판정

```powershell
pnpm --filter tools fit:confusion   # 학습 층위에서 비용표를 만든다 → tools/out/confusion.json
pnpm --filter tools bench:voice     # 네 구성을 재고 사전 등록 게이트로 판정한다
```

게이트는 `tools/src/bench-voice.ts`의 `GATE`에 **재기 전에** 적혀 있다.

| 항목 | 기준 |
|---|---|
| 1순위 상승 (④ vs ①) | +8%p 이상 |
| 잘못된 확신 증가 | 0건 |
| 추가 지연 p95 | 30ms 이하 |
| 텍스트 회귀 | 0건 (`bench:search`·`bench:sites`를 잃지 않을 것) |

**수치를 보고 게이트를 고치지 않는다.** 고쳐야 할 이유가 생기면 기획안에 먼저 적는다.
못 넘으면 `phonology.enabled`·`nbest.enabled`를 켜지 않고 수치를 §16에 남긴다 —
`neural.enabled`와 같은 처분이다.

## 결과 (2026-09-05)

게이트를 **홀드아웃 화자(B1, 141줄)에서 통과**했다. 수치와 해석은 `docs/기획안.md` §12.11에 있다.

| 항목 | 기준 | 결과 |
|---|---|---|
| 1순위 상승 | +8%p | **+8.2%p** |
| 잘못된 확신 증가 | 0건 | **0건** |
| 추가 지연 p95 | 30ms | **+23.73ms** |
| 텍스트 회귀 | 0건 | 통과 — 오히려 `bench:search` 98→100%, `bench:sites` 85→89% |

`search.phonology.enabled`·`search.nbest.enabled`는 이 판정으로 켰고, 학습된 표는
`search.confusion`에 실렸다.

**남은 한계는 §12.11에 적어 두었다** — 화자가 둘뿐이고, 고령 사용자의 발화 특성은 아직
이 코퍼스에 없으며, 지연은 데스크톱 기준이다.

> **하지 말 것.** 질의를 `pronounce()`한 형태로 만들어 재는 것은 순환이다 — 질의와 라벨이
> 같은 변환을 거치니 당연히 맞는다. §16의 뜻풀이 색인이 blind 세트에서 +31.7%p인데 사람이
> 쓴 질의에서 −6.7%p였던 것과 같은 함정이다. **실제 인식기를 지난 문자열만 쓴다.**
