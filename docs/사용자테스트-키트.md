# 사용자 테스트 키트 (M10)

**진행자용.** 인쇄해서 들고 간다. 근거와 배경은 `기획안.md` §12.2-B · §12.9 · §12.10에 있다.

참가자 8명 — 60대 이상 5명(P01~P05), 40~50대 저빈도 사용자 3명(P06~P08).
한 세션 약 45분. **§0은 세션 며칠 전, §1부터가 당일이다.**

# 세션 며칠 전

## 0. 사람 모으기

### 누구를 부르는가

| | 몇 명 | 조건 |
|---|---|---|
| **60대 이상** | 5명 (P01~P05) | 스마트폰으로 앱을 써 본 적은 있다. 은행 앱은 어려워한다 |
| **40~50대** | 3명 (P06~P08) | **저빈도** — 은행 앱을 주 1회 이하로 연다 |

8명이 안 모이면 **모인 만큼 하고 그대로 적는다.** 인원을 채우려고 조건을 늘리는 순간
재려던 대상이 바뀐다. 인원이 적을 때 무엇을 쓸 수 있고 무엇을 못 쓰는지는 맨 아래
「보고할 때」에 있다.

### 부르면 안 되는 사람

- **이 화면을 전에 본 사람** — 만든 사람, 개발 중에 구경한 가족·친구
- **개발자·디자이너·기획자** — 메뉴 분류 체계를 이미 아는 직업이다
- **은행 앱을 매일 쓰는 40~50대** — 저빈도가 조건이다. 능숙한 사람은 60대 칸에도 40대 칸에도 안 맞는다

### 모집할 때 하는 말

**무엇을 재는지 미리 말하지 않는다.** "새로 만든 쉬운 화면이 더 나은지 봐 주세요"라고
하면 참가자가 그 쪽을 편들려고 한다. 두 화면 중 하나가 우리 것이라는 사실 자체를 말하지 않는다.

> 안녕하세요. 은행 앱 화면을 새로 만드는 일을 하고 있는데, **실제로 쓰시는 분들이
> 써 보시고 어디가 불편한지 말씀해 주시는 자리**를 마련하려고 합니다.
>
> - 은행 앱 화면 **두 가지**를 써 보시면서, 몇 가지를 찾아보시는 겁니다
> - **40분에서 1시간쯤** 걸립니다
> - **가짜 화면이라 실제 돈은 전혀 움직이지 않습니다.** 계좌번호나 비밀번호 같은 건
>   여쭤보지 않습니다
> - **잘하고 못하고를 보는 게 아닙니다.** 오히려 헤매시는 데가 있으면 그게 저희가
>   고쳐야 할 곳이라 제일 도움이 됩니다
> - 화면 녹화를 하는데, 얼굴은 안 찍고 기록에는 이름 대신 번호만 남습니다
>
> 혹시 시간 내주실 수 있을까요?

사례품을 준비했으면 **이때 말한다.** 세션 끝나고 꺼내면 답례가 아니라 보상처럼 되고,
그러면 "잘해야 한다"는 부담이 생긴다.

### 전화로 미리 거르는 세 문항

1. "요즘 은행 일은 주로 어떻게 보세요? 스마트폰 앱이요, 인터넷이요, 아니면 은행에 직접 가세요?"
   → 스마트폰 앱을 **한 번도 안 써 보셨으면** 이번 대상이 아니다. 화면이 아니라
     스마트폰 조작 자체가 변수가 된다
2. (40~50대만) "은행 앱은 보통 얼마나 자주 여세요?"
   → **주 2회 이상이면** 저빈도 칸에 안 맞는다
3. "혹시 제가 만들고 있는 화면을 전에 보신 적 있으세요?"
   → 봤으면 안 된다

### 일정과 장소

- **1인당 60분**을 잡는다 (세션 45분 + 인사와 여유)
- **하루에 3명 넘게 잡지 않는다.** 진행자가 지치면 §6의 개입 기준이 제일 먼저 무너진다 —
  기다리기가 힘들어져서 자꾸 도와주게 된다
- **참가자가 편한 곳**이 낫다. 집, 경로당, 단골 카페. 낯선 사무실은 긴장을 만들고,
  긴장은 완료 시간에 그대로 실린다
- 조용해야 한다 — **음성 인식을 쓴다**

### 준비물

- [ ] 노트북 (**크롬**. 파이어폭스는 음성 인식이 아예 없다), 충전기
- [ ] 인터넷 — 음성 인식이 네트워크를 쓴다
- [ ] **초 단위가 보이는 시계나 타이머** (개입 60초를 잰다)
- [ ] 이 문서 인쇄본
- [ ] 동의서 인원수만큼 (§2)
- [ ] 기록 양식 인원수만큼 (§8)
- [ ] 필기구, 사례품

> **적어 둘 한계:** 실제 은행 앱은 손에 쥔 폰인데 이 데모는 노트북 화면이다. 손가락이
> 아니라 마우스로 누르는 것, 화면이 큰 것이 전부 변수다. 없앨 수 없으니 **결과에 그렇게
> 적는다.** 터치되는 노트북이나 태블릿이 있으면 그쪽이 낫다.

# 세션 당일

## 1. 세션 전 점검

**터미널 셋을 띄운다. 순서대로.** 하나라도 빠지면 화면이 빈 채로 뜬다 —
목으로 조용히 내려가지 않는 것이 의도다.

- [ ] ① Docker Desktop을 켠다 (GUI 앱. 고래 아이콘이 초록이 될 때까지 기다린다)
- [ ] ② **DB** — `docker compose -f backend/compose.yaml up -d`
      (이건 PostgreSQL만 띄운다. 이것만으로는 백엔드가 안 뜬다)
- [ ] ③ **계정계** — `cd backend && ./gradlew bootRun` (8080. 첫 실행은 몇 분 걸린다)
- [ ] ④ **프런트** — `pnpm --filter frontend dev` (5173)
- [ ] **`?stt=script`를 붙여** 열었다 — `http://localhost:5173/?stt=script`
- [ ] 콘솔에 `minuiMetrics`와 `minuiStt`가 **둘 다** 있다 (둘 중 하나라도 `undefined`면 중단하고 고친다)
- [ ] 마이크 권한을 **미리** 허용해 뒀다 (참가자 앞에서 팝업이 뜨면 F9가 날아간다)
- [ ] 참가자 번호를 확인했다 — **홀수는 쉬운 모드 먼저, 짝수는 기본 UI 먼저**
- [ ] **저장소를 비웠다** — 앞 참가자의 사용 기록·배운 말이 남으면 카드 배치가 달라진다.
      개발자 도구 → Application → IndexedDB → **`minui`** → **`state`** → `demo` 행을 지우거나
      `minui` 데이터베이스를 통째로 삭제한 뒤 **새로고침**

      > DB 이름은 `minui`이고 `demo`는 그 안의 **키**다(`IndexedDbStorageAdapter`).
      > `demo`라는 이름의 데이터베이스를 찾으면 없어서, 안 지우고도 지운 줄 알게 된다.
- [ ] 개발자 도구 창을 참가자에게 **안 보이게** 옮겼다
- [ ] 녹화를 켰다
- [ ] 동의서에 서명을 받았다

## 3. 시작 인사말

**그대로 읽는다.** 특히 "화면을 시험하는 것"과 "생각을 소리 내어" 두 대목은 빼먹으면
세션 전체가 달라진다.

> 시간 내주셔서 감사합니다. 오늘 하실 일을 먼저 말씀드릴게요.
>
> 은행 앱처럼 생긴 **가짜 화면** 두 가지를 준비했습니다. 제가 "이런 걸 해 보세요" 하고
> 몇 가지 말씀드리면, 화면에서 찾아서 해 보시면 됩니다.
>
> **중요한 건, 제가 시험하는 건 화면이지 참여자님이 아니라는 겁니다.** 못 찾으시거나
> 헤매시면 그건 **화면을 잘못 만든 제 탓**이에요. 오히려 그런 데를 찾으려고 하는 자리니까,
> 편하게 해 주시면 됩니다.
>
> 한 가지 부탁이 있는데요. **지금 무슨 생각 하시는지 소리 내어 말씀해 주세요.**
> "이게 뭐지", "여기 있으려나" 이런 거요. 혼잣말하듯이 하시면 됩니다. 그래야 제가
> 어디서 헷갈리시는지 알 수 있어요.
>
> 그리고 제가 중간에 **일부러 말을 안 하고 가만히 있을 때가 있습니다.** 답을 알면서
> 숨기는 게 아니라, 도와드리면 화면이 좋은 건지 제가 도와드린 건지 알 수 없게 돼서
> 그렇습니다. 답답하셔도 조금만 이해해 주세요.
>
> 언제든 그만하고 싶으시면 말씀하세요. 시작하기 전에 궁금한 거 있으실까요?

## 4. 과제 지시문

**그대로 읽는다.** 메뉴 이름을 입에 올리지 않는다 — 참가자가 그 말을 그대로 검색창에
치고, 재려던 것(**그 기능을 뭐라고 부르는가**)이 사라진다.

> ### T1
> ### "이번 달 관리비가 빠져나갔는지 궁금하세요. 통장에 얼마 남았는지 보세요."

<sub>목표 `inquiry.balance` · `minuiMetrics.begin("T1", "inquiry.balance", "minui")`</sub>

> ### T2
> ### "매달 자동으로 나가는 전기요금이 있는데, 이제 그만 나가게 하고 싶으세요."

<sub>목표 `transfer.auto` · `minuiMetrics.begin("T2", "transfer.auto", "minui")`</sub>

> ### T3
> ### "은행에서 '한 번에 보낼 수 있는 돈이 막혀 있으니 앱에서 푸세요'라고 했습니다."

<sub>목표 `settings.limit` · `minuiMetrics.begin("T3", "settings.limit", "minui")`</sub>

**세 번째 인자는 그때 참가자가 쓰고 있는 모드로 바꿔 넣는다** (`"minui"` 또는 `"classic"`).
틀리면 두 모드가 한쪽으로 합쳐져 비교가 없어진다. **가장 흔한 실수다.**

## 5. 진행 순서

| | 홀수 참가자 (P01·P03·P05·P07) | 짝수 참가자 (P02·P04·P06·P08) |
|---|---|---|
| 1 | **쉬운 모드**로 T1 → T2 → T3 | **기본 UI**로 T1 → T2 → T3 |
| 2 | **기본 UI**로 T1 → T2 → T3 | **쉬운 모드**로 T1 → T2 → T3 |
| 3 | F9 (§7) | F9 (§7) |
| 4 | T2 반복 (아래) | T2 반복 (아래) |
| 5 | 사후 인터뷰 (§9) | 사후 인터뷰 (§9) |

과제마다 시작 직전에 `minuiMetrics.begin(...)`을 친다. **완료는 자동으로 잡힌다.**
참가자가 끝내 못 하면 `minuiMetrics.abandon()`.

**T2 반복**은 `minuiMetrics.begin("T2-repeat", "transfer.auto", "minui")`로 연다.
같은 `"T2"`로 열면 1차 지표에 학습 효과가 섞인다.

### 사이사이 하는 말

**과제가 끝나면** — 성공했든 못 했든 **같은 말**을 한다. "잘하셨어요"는 못 찾았을 때
거짓말이 되고, 찾았을 때는 정답을 알려 준 셈이 된다.

> "네, 여기까지 하겠습니다. 다음 걸로 넘어갈게요."

**모드를 바꿀 때** — 두 화면 중 어느 쪽이 우리 것인지 티내지 않는다.

> "이번엔 화면 방식을 바꿔서, 같은 걸 다시 해 보실게요."

**T2 반복 직전** — 반복이라는 걸 강조하면 "아까 그거잖아"가 되어 낱말이 아니라
기억을 잰다. 아무 설명 없이 지시문만 다시 읽는다.

**참가자가 "이거 맞아요?" 하고 물으면**

> "편하신 대로 해 보세요. 제가 답을 드리면 화면이 좋은 건지 알 수 없게 돼서요."

## 6. 개입 기준

**개입 시점이 사람마다 다르면 완료율이 진행자의 인내심을 재게 된다.** 시계를 본다.

| 조건 | 하는 말 | 기록 |
|---|---|---|
| **60초** 무진전 (새 화면 진입 없음) | "지금 무엇을 찾고 계신지 말씀해 주시겠어요?" | 개입 **1** |
| **추가 60초** 무진전 | "화면에서 눈에 들어오는 걸 소리 내어 읽어 주세요." | 개입 **2** |
| **추가 60초**, 또는 참가자가 포기 의사 | "여기까지 하겠습니다. 이건 화면이 어려운 겁니다." | 개입 **3** = 중단·미완료 |

### 하면 안 되는 것

- 메뉴 이름 말하기
- "거기 아니에요" / "다시 보세요"
- 화면 가리키기
- **참가자가 옳은 방향일 때 고개 끄덕이기** — 이것도 힌트다

### think-aloud

시작할 때 §3에서 한 번 부탁했다. 그 뒤로는 **침묵 15초에 한 번만** 다시 유도한다.

> "지금 무슨 생각 하고 계세요?"

계속 재촉하면 말하느라 완료 시간이 늘어난다 — 재려는 것을 재는 행위가 바꿔 버린다.

## 7. F9 프로토콜 — 금액 제안

**쉬운 모드에서, 두 모드가 다 끝난 뒤 1회.**

F9가 묻는 것: **말한 금액과 다른 금액이 제안으로 떴을 때 잡아내는가.**

### 순서

1. 콘솔에 미리 친다 (참가자에게 말하기 **전에**):

   ```js
   minuiStt.next("우리 딸한테 십삼만원 보내줘")
   ```

2. `minuiMetrics.begin("F9", "transfer.account", "minui")`
3. 지시문을 읽는다:

   > ### "따님께 **삼십만원**을 보내려고 하세요. 말로 해 보세요."

4. 참가자가 마이크를 누르고 "삼십만원"이라고 말한다
5. 이체 화면의 금액 제안에 **13만원**이 뜬다
6. **아무 말 없이 본다**

> ⚠️ **넣어 둔 문장은 첫 인식에서 소진된다. 인식이 실패해도 소진된다.**
> 참가자가 마이크를 잘못 눌러 한 번 헛돌면 그때 나가 버린다.
> **13만원이 안 떴으면 `minuiStt.next(...)`를 다시 치고 한 번 더 시킨다.**
> (인식 실패에도 나가게 만든 건 의도다 — 고령 발화에서 STT가 흔들릴 때마다
> 프로토콜이 무너지면 F9를 잴 기회가 사라진다.)

### 세 갈래 — 하나에 동그라미

| 관찰 | 뜻 | 기록 값 |
|---|---|---|
| 읽고, 틀렸으니 **안 누른다** | 제안이 안전 장치로 작동한다. 지금 설계가 맞다 | `read-not-tapped` |
| **안 읽고 누른다** | 탭 한 번을 더 요구했을 뿐 안전은 늘지 않았다. 금액 경로를 다시 봐야 한다 | `tapped-unread` |
| 아예 안 누르고 **직접 친다** | 제안이 값을 못 한다. 금액을 아예 읽지 않는 편이 정직하다 | `typed-instead` |

**해명은 세션 끝(§10)에서 한다.** 여기서 바로 말하면 남은 인터뷰 내내 "속았다"는
기분이 답에 실린다.

## 11. 세션 후

1. 콘솔에서 회수한다:

   ```js
   copy(minuiMetrics.toJSON())
   ```

   **새로고침하기 전에 한다.** 기록은 메모리에만 있다.

2. `tools/sessions/P01.json`을 만들고 봉투에 넣는다.
   **형식은 `tools/sessions/EXAMPLE.json`을 복사해서 쓴다.**

   ```json
   {
     "participant": "P01",
     "ageBand": "60+",
     "firstMode": "minui",
     "runs": [ 붙여넣기 ],
     "interventions": { "T2:classic": 2 },
     "words": { "T2": ["자동으로 나가는 거", "그 매달 빠지는 거"] },
     "f9": "read-not-tapped",
     "m7Repeat": "same"
   }
   ```

   - `ageBand` — `"60+"` 또는 `"40-50"`
   - `firstMode` — 그 참가자가 **먼저** 쓴 모드
   - `interventions` — `"과제:모드"` → 개입 단계. 개입이 없었으면 넣지 않는다
   - `words` — 기록 양식의 낱말을 **발화 순서대로**. 마지막 원소가 T2 반복의 것이다
   - `f9`·`m7Repeat` — 안 했으면 필드를 뺀다

3. 집계한다:

   ```bash
   pnpm --filter tools report:usertest
   ```

4. [ ] 녹음 원본을 폐기했다 (기획안 §11.2)

> **파일럿(리허설) 기록은 `tools/sessions/`에 넣지 않는다.** 넣으면 없는 참가자가
> 표에 서고 참가자 수가 틀리게 찍힌다.

## 보고할 때

**표본 8명에 통계적 검정력이 없다. 유의성을 주장하지 말고 관찰된 패턴과 개별 사례로
보고한다.** 그리고 이 프로젝트가 여러 번 그랬듯, **미달한 지표를 그대로 적는다** —
목표를 맞추려고 기준을 옮기지 않는다.

### 인원이 8명에 못 미쳤다면

| 모인 인원 | 쓸 수 있는 것 | 쓸 수 없는 것 |
|---|---|---|
| **5~7명** | 1차 지표 세 칸을 **참가자 수를 명시해서** 적는다 | 여전히 유의성 주장은 못 한다 |
| **3~4명** | 관찰 항목(낱말·F9 세 갈래·멈춘 지점)은 그대로 쓴다 | 완료 시간 비교, 순서 효과 |
| **1~2명** | **사례 N건**으로만 적는다 | 시간·비율 전부. §12.1 세 칸은 미측정으로 남는다 |

2명의 중앙값은 두 값의 평균일 뿐이고, 2/2와 1/2밖에 안 나오는 비율은 비율이 아니다.
**"참가자 2명, 완료율 100%"라고 쓰는 것이 최악이다.**

### 어느 쪽이든 T1을 눈여겨본다

§12.4에서 탭 차이가 0%였던 자리다. **탭이 0:0인데 완료 시간이 갈리는지**가
"탭 횟수는 난이도의 하한이고 조밀한 UI에 유리하게 편향된다"는 주장의 유일한
시험대다. 안 갈리면 그 주장도 접는다.
